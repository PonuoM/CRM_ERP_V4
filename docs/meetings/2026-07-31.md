## 🎯 เกณฑ์จัดลำดับที่ใช้ (Prioritization Rubric)

จัดลำดับด้วย 4 ประตูตามลำดับ — ผ่านประตูบนก่อนเสมอ ไม่ใช่ให้คะแนนรวม:

| # | ประตู | คำถาม | ผลถ้า "ใช่" |
|---|---|---|---|
| **G1** | **มีเดดไลน์ที่รับปากไปแล้ว** | มีวันที่ประกาศกับทีม/ผู้บริหารแล้วหรือยัง | → ล็อกเข้า Wave ที่คำนวณย้อนจากวันนั้น |
| **G2** | **บล็อกความถูกต้องของข้อมูลหรือเงิน** | ถ้าไม่ทำ ตัวเลขที่ใช้ตัดสินใจ/จ่ายเงิน จะผิด | → P0 ทันที ไม่ว่าจะยากแค่ไหน |
| **G3** | **ถูก/คุ้ม (Quick Win)** | ≤1 วัน แต่แก้ปัญหาที่ทีมเจอทุกวัน | → แทรกคู่ขนานกับงานใหญ่ |
| **G4** | **รอคนตัดสินใจ** | ยังไม่มีตัวเลข/นิยามที่ชัด | → **ไม่ใช่งาน dev** ย้ายไปตาราง "รอตัดสินใจ" |

> ⚠️ กฎเหล็ก: งานที่ติด G4 **ห้ามเอาไปนับเป็นงานค้างของ dev** — มันค้างที่ฝั่งธุรกิจ ไม่ใช่ฝั่งโค้ด
> ให้ไล่ตอบให้ครบก่อน แล้วค่อยดันเข้า Wave

**สเกล Effort**: `XS` <0.5 วัน · `S` 0.5–1 วัน · `M` 2–3 วัน · `L` 1–2 สัปดาห์ · `XL` >2 สัปดาห์

|---|---|---|

| 3 | **หน้าแคมเปญเปรียบเทียบ ทำไปแล้ว ~80%** — [api/Reports/telesale_campaign_compare.php](../../api/Reports/telesale_campaign_compare.php) มี per-agent × per-segment × 2 เดือน + segment filter อยู่แล้ว | เหลือแค่ **verify + อุดช่อง** ไม่ใช่สร้างใหม่ |
| 4 | **`order_tags` เพิ่งถูกสร้าง** (migration 070, commit `6e0943d9`) | ใช้เป็นทางลัดของ "แยกออเดอร์โทรเข้า/โทรออก" ได้ทันที ก่อนทำ auto-detect เต็มรูปแบบ |
| 5 | **`customer_grades_config` + `customer_grades_settings` มีอยู่แล้ว** รองรับ threshold + `relative_days` (365) + สีป้าย | Tier/Member Card ไม่ต้องเริ่มจากศูนย์ — ต่อยอดของเดิมได้ |

## ⚠️ ข้อควรระวังทางเทคนิค (ก่อนลงมือ)

| # | เรื่อง | ผลถ้าพลาด |
|---|---|---|
| 1 | **ยอดขายพอง** — `SUM(net_total)` พอง 3–11× ในบิล import เก่า; `price_per_unit` ปี 2025 บางบิลเก็บยอดรวมบรรทัดแล้วคูณ qty ซ้ำ | ตั้ง Tier ผิด → แจกส่วนลดเกินจริง (CRM-13, CRM-14) |
| 2 | **`call_history.duration` ใช้ไม่ได้** (เกือบ 0 หมด) — duration จริงอยู่ที่ `call_import_logs` (rec_type=2, `matched_user_id`, เบอร์ลูกค้า 66→0) | Talk Time ทั้งหมดผิด (CRM-02, CRM-03, CRM-07) |
| 3 | **`call_history.date` เก็บเป็นเวลาไทย local อยู่แล้ว** — `CONVERT_TZ +7` ในโค้ดเก่าเป็น latent bug | หน้าต่าง 07:00–18:30 จะเลื่อน 7 ชั่วโมง (CRM-03) |
| 4 | **`basket_config` เป็น global** (`company_id = 1` เสมอ) | แก้ถัง 6 เดือน = กระทบทุกบริษัท ไม่ใช่แค่บริษัทเดียว (CRM-20) |
| 5 | **Deploy split** — prod รัน `config.php` ที่ root ไม่ใช่ `api/config.php` | helper ที่เพิ่มแค่ `api/config.php` จะ undefined บน live |
| 6 | **Frontend cache** — ต้องให้ user hard-refresh หลัง deploy ครั้งแรก | แก้แล้วแต่ user ยังเห็นของเก่า |
| 7 | **`CreateOrderPage.tsx` ใหญ่มาก (>10,000 บรรทัด)** | CRM-21 และ ERP-08 จะแตะไฟล์เดียวกัน — **อย่าทำพร้อมกัน** จะชนกันหนัก |
