# 📸 Snapshot "ลูกค้าที่ดูแล" รายเดือน — คู่มือติดตั้ง

ทำให้คอลัมน์ **ลูกค้าที่ดูแล** ในหน้า *แคมเปญรายคน* (`?page=Telesale+Campaign+Compare`)
แสดง **ยอด ณ วันสุดท้ายของแต่ละเดือน (ก่อนระบบดึงลูกค้ากลับ)** แทนที่จะเป็นยอด ณ ตอนนี้

---

## 🎯 ปัญหาเดิม

คอลัมน์นี้อ่านสดจากตาราง `customers` (`assigned_to` + `current_basket_key`) ทุกครั้งที่เปิดหน้า
ผลคือ:

- ทั้งสองเดือนที่เอามาเทียบ **แสดงเลขเดียวกัน** (ยอดวันนี้) เทียบกันไม่ได้
- ยอดที่เห็นเป็นยอด **หลังระบบดึงกลับ** ไปแล้ว — cron `monthly_cron`
  (`api/cron/monthly_basket_transfer.php`) ถอด `assigned_to` ทีละแสนรายตอน **01:00 ของวันที่ 1**
  ทุกเดือน ลูกค้าในมือ telesale เลยดู "หาย" ทั้งที่ตอนเขาทำงานจริงมีอยู่

ตัวอย่างของจริง (company 1): สิ้น พ.ค. 69 ก่อนดึงกลับมี **80,067** ราย หลังดึงกลับเหลือ **25,116** ราย

---

## 🧱 โครงสร้าง

| ส่วน | ไฟล์ |
|---|---|
| ตาราง snapshot ยอดรวม (รายวัน) | `api/migrations/074_create_customer_ownership_snapshots.sql` |
| ตาราง snapshot รายลูกค้า (สิ้นเดือน) | `api/migrations/075_create_customer_basket_snapshots.sql` |
| Cron เก็บรายวัน | `api/cron/snapshot_customer_ownership.php` |
| Backfill ย้อนหลัง | `api/cron/backfill_ownership_snapshots.php` |
| ฟังก์ชันร่วม | `api/cron/ownership_snapshot_lib.php` |
| API ที่ใช้ค่า | `api/Reports/telesale_campaign_compare.php` |
| หน้าจอ | `pages/TelesaleCampaignComparePage.tsx` |

มี 2 ตาราง เพราะใช้คนละงาน:

**1. `customer_ownership_snapshots`** — ยอดรวม 1 แถวต่อ (วันที่, บริษัท, agent, ถัง)
เก็บ**ทุกวัน** ≈ 460 แถว/วัน ทุกบริษัทรวมกัน (≈ 170K แถว/ปี) → ใช้เติมคอลัมน์ "ลูกค้าที่ดูแล"

**2. `customer_basket_snapshots`** — รายลูกค้า 1 แถวต่อ (วันที่, customer_id)
เก็บ**เฉพาะสิ้นเดือน** ≈ 234K แถว/เดือน (~15 MB/เดือน) → ใช้บอกว่าสายที่โทรในเดือนนั้น
ควรนับเข้าถังไหน (ดูหัวข้อ "ทำไมต้องมีตารางรายลูกค้า")

ทั้งสองตารางเขียนพร้อมกันเสมอ ยอดรวมคำนวณจากรายลูกค้าโดยตรง เลขจึงตรงกันเสมอ

| คอลัมน์ | ความหมาย |
|---|---|
| `snapshot_date` | วันที่ที่ค่านี้แทน |
| `company_id`, `agent_id`, `basket_key` | มิติของยอด (`basket_key` = `basket_config.id` เป็น string, `''` = ไม่มีถัง) |
| `owned_count` | จำนวนลูกค้า |
| `is_month_end` | 1 = เป็นยอดสิ้นเดือน |
| `captured_at` | เวลาจริงที่ state นี้แทน |
| `source` | `cron` (เก็บสดคืนนั้น) / `backfill` (ย้อนสร้าง) / `manual` |

## ⚙️ ติดตั้ง (ทำครั้งเดียว)

### 1. สร้างตาราง

รัน `api/migrations/074_create_customer_ownership_snapshots.sql`
และ `api/migrations/075_create_customer_basket_snapshots.sql` บน production
(**ทำแล้ว** เมื่อ 2026-08-03)

### 2. ตั้ง cron รายวัน — ⚠️ ต้องทำ

```
50 23 * * *  curl -s "https://www.prima49.com/mini_erp/api/cron/snapshot_customer_ownership.php?key=ownership_snapshot_2026_secret&dryrun=0"
```

**เวลา 23:50 สำคัญ** — ต้องอยู่ก่อน `monthly_cron` ที่รัน 01:00 ของวันที่ 1
ไม่งั้นจะได้ยอดหลังดึงกลับ (คือปัญหาเดิม)

ทดสอบก่อนได้ด้วย `&dryrun=1` (ค่า default ของฝั่ง URL คือ dry run อยู่แล้ว)

รันซ้ำวันเดิมได้ ไม่เกิดข้อมูลซ้ำ — จะเขียนทับทั้งวัน

### 3. Backfill เดือนเก่า

```bash
# ดูก่อน
php api/cron/backfill_ownership_snapshots.php --from=2026-02 --to=2026-07 --dry-run
# เขียนจริง
php api/cron/backfill_ownership_snapshots.php --from=2026-02 --to=2026-07
```

หรือผ่าน URL: `...backfill_ownership_snapshots.php?key=ownership_snapshot_2026_secret&dryrun=0&from=2026-02&to=2026-07`

เดือนที่มีข้อมูลอยู่แล้วจะถูกข้าม เว้นแต่ใส่ `--force`
(กันไม่ให้ backfill ทับแถวที่ cron เก็บมาจริง ซึ่งแม่นกว่า)

## 🔬 Backfill ย้อนหลังทำได้ยังไง

`basket_transition_log` เก็บ **สถานะก่อนย้าย** ของทุกครั้งที่ลูกค้าเปลี่ยนถัง/เปลี่ยนเจ้าของ
(`from_basket_key`, `assigned_to_old`) ดังนั้น:

> สถานะของลูกค้า ณ เวลา T = สถานะก่อนย้ายของ transition **แรกที่เกิดหลัง T**
> ถ้าไม่มี transition หลัง T เลย = สถานะปัจจุบัน

(วิธีเดียวกับที่รายงาน [REPORT_BASKET_FLOW_GUIDE.md](REPORT_BASKET_FLOW_GUIDE.md) ใช้อยู่แล้ว)

### ความแม่นยำ

ตรวจสอบโดยย้อนสร้างจาก **`customer_audit_log`** (`field_name` = `assigned_to` / `current_basket_key`)
ซึ่งเป็นแหล่งข้อมูลคนละตัวกัน แล้วเทียบกันรายลูกค้า:

| สิ้นเดือน | ตรงกัน | ผลต่างยอดรวม |
|---|---:|---:|
| มี.ค. 69 | 99.74% | 5 / 77,217 |
| เม.ย. 69 | 99.52% | 9 / 69,803 |
| พ.ค. 69 | 97.54% | 132 / 25,116 |
| มิ.ย. 69 | 99.52% | 40 / 59,903 |
| ก.ค. 69 | 99.71% | 4 / 47,603 |

→ คลาดเคลื่อนระดับ 0.01–0.5% หน้าจอจึงติดป้าย **"ประมาณการ"** ให้เดือนที่มาจาก backfill

### ข้อจำกัด

1. **ย้อนได้ถึง ก.พ. 69 เท่านั้น** — `basket_transition_log` เริ่ม 24 ม.ค. 69
   สคริปต์ปฏิเสธถ้าสั่งย้อนก่อนหน้านั้น
2. **`from_basket_key` มี 2 รูปแบบ** — ทั้งเลข (`39`) และ slug (`personal_1_2m`)
   สคริปต์แปลง slug → id ผ่าน `basket_config` ก่อนเก็บ
   ค่าที่ไม่ใช่ถังจริง (`Multiple Baskets`, ค่าว่าง) นับเป็น "ไม่มีถัง"
3. **cron ดึงกลับไม่ได้รันเวลาเดิมเสมอ** — 31 พ.ค. 69 รันเร็วตอน 21:27
   สคริปต์จึงหา burst แรกของแต่ละเดือน ถ้าตกวันสุดท้ายจะตัดก่อนหน้านั้น 1 วินาที

## 🧮 ทำไมต้องมีตารางรายลูกค้า (`customer_basket_snapshots`)

พอ "ลูกค้าที่ดูแล" กลายเป็นยอดสิ้นเดือน แต่ "ชื่อที่โทร" ยังจัดกลุ่มตาม**ถังวันนี้** เลขในแถวเดียวกันจะขัดกัน
เคสจริง (กล๊อฟ ก.ค. 69, ถังส่วนตัวโอกาสสุดท้าย):

| จัดกลุ่มด้วย | ลูกค้าที่ดูแล | ชื่อที่โทร |
|---|---:|---:|
| ถังวันนี้ (ของเดิม) | 19 | **100** ❌ |
| ถัง ณ 31 ก.ค. (ปัจจุบัน) | 19 | **15** ✅ |

คนที่โทรไป 15 คนนั้นย้ายไปถัง "พักรอแจก" หมดแล้วหลังสิ้นเดือน โค้ดเดิมจึงนับเขาไว้ในถังที่เขาอยู่ *วันนี้*

API จึงหา snapshot_date ของแต่ละเดือน **ครั้งเดียว** แล้วใช้ค่าเดียวกันทั้งฝั่ง "ลูกค้าที่ดูแล"
และฝั่งการโทร — สองคอลัมน์ไม่มีทางอ้างอิงคนละเวลาได้อีก

| คอลัมน์ | อิงถัง ณ |
|---|---|
| ลูกค้าที่ดูแล | สิ้นเดือนนั้น |
| ชื่อที่โทร / สายโทร / ได้คุย | สิ้นเดือนนั้น |
| ออเดอร์ / ยอดขาย | ตอนขาย (`order_items.basket_key_at_sale` — แม่นกว่า ไม่ต้องแก้) |

### ⚠️ "ชื่อที่โทร > ลูกค้าที่ดูแล" ยังเกิดได้ และไม่ใช่บั๊ก

ทั้งสองคอลัมน์เป็นคนละชนิดกัน — **ชื่อที่โทร = flow (ทั้งเดือน)** แต่ **ลูกค้าที่ดูแล = stock (ณ สิ้นเดือน)**
telesale โทรหาคนที่ไม่ใช่ลูกค้าตัวเองได้ และคนที่โทรระหว่างเดือนอาจหลุดมือไปก่อนสิ้นเดือน

วัดจริงจากข้อมูล มิ.ย.–ก.ค. 69 บริษัท 1: 670 ช่อง (segment × เดือน) มี 89 ช่อง (13%) ที่โทร > ดูแล
แต่ส่วนเกินรวมแค่ **1,573 จากสายที่โทร 55,282 = 2.85%** และเป็นตัวเลขหลักหน่วย–หลักสิบแทบทั้งหมด
(เทียบกับก่อนแก้ที่ช่องเดียวต่างกัน 100 vs 19)

## 🖥️ หน้าจอเปลี่ยนยังไง

**เดิม**: `[ทีม/Agent/Segment] [ลูกค้าที่ดูแล] [เดือน B: 5 คอลัมน์] [Diff] [เดือน A: 5 คอลัมน์]`

**ใหม่**: `[ทีม/Agent/Segment] [เดือน B: ลูกค้าที่ดูแล + 5 คอลัมน์] [Diff] [เดือน A: ลูกค้าที่ดูแล + 5 คอลัมน์]`

ป้ายกำกับข้างหัวเดือน:

| ป้าย | ความหมาย |
|---|---|
| (ไม่มีป้าย) | ยอดสิ้นเดือนจริง เก็บโดย cron คืนนั้น |
| **ประมาณการ** | ย้อนสร้างจาก `basket_transition_log` |
| **ยอดปัจจุบัน** | เดือนยังไม่จบ (หรือยังไม่มี snapshot) จึงแสดงยอด ณ ตอนนี้ |

ไฟล์ Export มีคอลัมน์ `ลูกค้าที่ดูแล` อยู่ในบล็อคของแต่ละเดือน และหัวเดือนระบุที่มาของตัวเลข

## ✅ ตรวจสอบว่าใช้งานได้

```sql
-- มี snapshot เดือนไหนแล้วบ้าง
SELECT snapshot_date, source, COUNT(*) rows_, SUM(owned_count) owned
FROM customer_ownership_snapshots
GROUP BY snapshot_date, source ORDER BY snapshot_date;

-- ยอดของ company 1 แยกตามเดือน
SELECT snapshot_date, SUM(owned_count) owned
FROM customer_ownership_snapshots
WHERE company_id = 1 AND is_month_end = 1
GROUP BY snapshot_date ORDER BY snapshot_date;
```

ถ้า cron ทำงาน จะเห็นแถวใหม่ทุกวัน และ log อยู่ที่ `api/cron/logs/snapshot_customer_ownership_YYYY-MM.txt`
